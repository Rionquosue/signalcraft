# 2 - 9 Discord (YAGPDB) Ruby addon — specification sheet

Addon 1.0 • 22 October 2026 • plugin_id `discord_yagpdb` • kind `social` • relay protocol 1.0 (push)

## Purpose

Post scheduled news to a chosen Discord channel through your own self-hosted YAGPDB instance. This sheet covers both halves:

1. **YAGPDB fork:** a new Go plugin, `socialpub`, added to the open-source YAGPDB code, that implements the push side of the relay protocol (10_Relay_Bot_Protocol_Specification.md) and gives each connection a specific channel.
2. **Ruby addon:** the `discord_yagpdb` addon in the Rails application, which uses the shared relay addon base.

The public bot at yagpdb.xyz is not used.

## Facts about YAGPDB this design relies on

Checked against `github.com/botlabs-gg/yagpdb` at commit `d002e62` (22 October 2026). Re-check when you fork.

| Fact | Source in the code | Consequence |
|---|---|---|

| The message queue (`common/mqueue`) serializes messages to storage, and `discordgo.MessageSend.Files` is excluded from serialization; it does not report the sent message ID back to the source plugin | `common/mqueue/models.go`, `lib/discordgo/message.go`, `common/mqueue/discordprocessor.go` | The plugin sends directly with `common.BotSession.ChannelMessageSendComplex`, which supports file uploads and returns the message ID needed as delivery proof. |

### Tables

```sql
CREATE TABLE IF NOT EXISTS socialpub_destinations (
  id                   BIGSERIAL PRIMARY KEY,
  public_id            TEXT NOT NULL UNIQUE,          -- 'dst_' + 22 random base62 chars
  guild_id             BIGINT NOT NULL,
  channel_id           BIGINT NOT NULL,
  mention_role_ids     BIGINT[] NOT NULL DEFAULT '{}',
  allow_everyone       BOOLEAN NOT NULL DEFAULT FALSE,
  publish_announcement BOOLEAN NOT NULL DEFAULT FALSE,
  suppress_previews    BOOLEAN NOT NULL DEFAULT FALSE,
  token_digest         BYTEA NOT NULL,                -- SHA-256 of the relay token
  next_token_digest    BYTEA,                         -- second token during rotation
  enabled              BOOLEAN NOT NULL DEFAULT TRUE,
  problem              TEXT,                          -- missing_permission, channel_missing, ...
  created_at           TIMESTAMPTZ NOT NULL,
  updated_at           TIMESTAMPTZ NOT NULL
);
CREATE INDEX IF NOT EXISTS socialpub_destinations_guild_idx ON socialpub_destinations (guild_id);

CREATE TABLE IF NOT EXISTS socialpub_deliveries (
  id               BIGSERIAL PRIMARY KEY,
  destination_id   BIGINT NOT NULL REFERENCES socialpub_destinations (id) ON DELETE CASCADE,
  idempotency_key  TEXT NOT NULL,
  request_digest   BYTEA NOT NULL,                    -- SHA-256 of the canonical request body
  request          JSONB NOT NULL,
  status           TEXT NOT NULL,                     -- queued, sending, delivered, failed, unknown, cancelled
  attempts         INT NOT NULL DEFAULT 0,
  not_before       TIMESTAMPTZ NOT NULL,
  message_ids      BIGINT[] NOT NULL DEFAULT '{}',
  error_code       TEXT,
  error_retryable  BOOLEAN,
  delivery_state   TEXT,
  created_at       TIMESTAMPTZ NOT NULL,
  updated_at       TIMESTAMPTZ NOT NULL,
  delivered_at     TIMESTAMPTZ,
  UNIQUE (destination_id, idempotency_key)
);
CREATE INDEX IF NOT EXISTS socialpub_deliveries_due_idx
  ON socialpub_deliveries (not_before) WHERE status = 'queued';
```

Only token digests are stored, so a YAGPDB database leak does not expose a usable token. Delivery rows older than 30 days are deleted by the feed loop.

### Control panel page

A "Social Publisher" item in the Feeds section of the server's control panel, with the same middleware as RSS (`RequireBotMemberMW`, plus a manage-server permission check).

- **Add destination:** pick a text or announcement channel, optional roles to mention, "Allow @everyone" (off by default), "Publish to followers" (announcement channels only) and "Hide link previews".
- On save, the page shows once: the relay base URL, the destination ID and a new relay token, with copy buttons, for pasting into the Rails "Connect Discord (YAGPDB)" form.
- **Rotate token:** issues a second token; the old one stops working when the owner clicks "Revoke old token".
- **Status:** the channel, the last delivery time, and any problem (for example "The bot can't attach files in #news").
- Actions are recorded in YAGPDB's control panel log (`cplogs`), like RSS.
- No per-server cap beyond a configurable maximum (default 10 destinations), since this is your own instance.

### Relay API

Registered on `web.RootMux` under `/relay/v1/`, outside the control panel's Discord login, protected only by the relay token:

| Route | Behavior |
|---|---|
| `GET /relay/v1/destinations/{id}` | Look up by `public_id`; compare the bearer token's SHA-256 with `token_digest` or `next_token_digest` in constant time; unknown ID or wrong token both return 404. Check the bot's permissions in the channel (View Channel, Send Messages, Attach Files, Embed Links, plus Mention Everyone if roles or @everyone are mentioned) and return `can_post` and `problem`. |
| `POST /relay/v1/deliveries` | Validate the body against the destination's limits and options (422 on failure); insert with `ON CONFLICT (destination_id, idempotency_key) DO NOTHING`; if a row exists, compare `request_digest` (409 on mismatch) or return its current state. Return 202 for new deliveries. `not_before` is the later of now and `scheduled_for` minus 5 seconds. |
| `GET /relay/v1/deliveries/{key}` | Delivery resource as defined in sheet 10; `message_url` is `https://discord.com/channels/{guild}/{channel}/{message}`. |
| `DELETE /relay/v1/deliveries/{key}` | Cancel if still `queued`; otherwise 409 `not_cancellable` (message deletion is not offered in v1). |

The request body limit is 64 KiB. Requests are rate-limited per destination (default 60 per minute) using YAGPDB's Redis.

### Sender loop

Runs in the feeds service (`StartFeed` / `StopFeed`), polling every 5 seconds:

1. Claim up to 5 due deliveries with `UPDATE … SET status = 'sending', attempts = attempts + 1 … WHERE id IN (SELECT id … WHERE status = 'queued' AND not_before <= now() ORDER BY not_before FOR UPDATE SKIP LOCKED LIMIT 5) RETURNING …`.
2. Download each media item from its `fetch_url` with a 60-second timeout, keeping it in memory, and verify byte size and SHA-256. On mismatch, fail with `attachment_hash_mismatch` (`not_submitted`).
3. Build the message:
   - text as message content (plain; Discord markdown characters are escaped so the text appears exactly as written);
   - media as uploaded files, with alt text set as each attachment's description;
   - allowed mentions restricted to the destination's configured roles (and @everyone only if allowed), with the role mentions prepended to the text;
   - link embeds suppressed if "Hide link previews" is on.
4. Send with `common.BotSession.ChannelMessageSendComplex`. If the text is longer than one Discord message allows, split it at paragraph or word boundaries into several messages, attaching media to the first. Record every message ID.
5. If "Publish to followers" is on, crosspost each message. A crosspost failure is logged and reported in `error`, but the delivery stays `delivered`, since the message was posted.
6. Record the outcome:

| Outcome | Status | delivery_state |
|---|---|---|
| Message(s) sent | delivered | submitted |
| Discord returned a permission, missing-channel or validation error before posting | failed, retryable false; destination `problem` set | not_submitted |
| Discord rate limit or 5xx before posting | back to queued with `not_before` pushed back (up to 5 attempts), then failed retryable | not_submitted |
| Timeout or connection loss after the request was sent | unknown | unknown |
| Some parts of a split message sent, then an error | unknown (message_ids lists what was sent) | unknown |

7. On startup, any row left in `sending` (the process stopped mid-send) becomes `unknown` and is never resent automatically.

### Limits reported to Rails

| Limit | Default | Note |
|---|---|---|
| max_text_chars | 4000 | Discord's limit per message is 2000 characters for bot messages; longer text is split into up to two messages. Verify current limits when forking. |
| max_attachments | 10 | Discord's per-message attachment limit |
| max_attachment_bytes | 10485760 | Discord's default upload limit for servers without boosts; set higher if your server's boost level allows. Verify against current Discord limits. |
| media_types | JPEG, PNG, GIF, WebP, MP4 | Rails converts other formats before delivery |

### Tests in the fork

Token checks and constant-time comparison, idempotent POST and 409 on body mismatch, permission problems reported before posting, hash mismatch, splitting long text, crosspost failure handling, restart during `sending` producing `unknown`, and the shared conformance suite from sheet 10 run against a test Discord guild.

## Part 2: Ruby addon `discord_yagpdb`

### Manifest

```yaml
id: discord_yagpdb
kind: social
name: Discord (via YAGPDB)
plugin_api: ">=1.2 <2.0"
auth:
  strategy: relay_token            # owner pastes relay URL, destination ID and token
capabilities:
  text: true
  images: true
  video: true
  audio: false
  alt_text: true
  requires_media: false
  media_fetch_by_url: false
  remote_idempotency: true         # the relay deduplicates by idempotency key
  reconciliation: true
  link_placement: in_post
  metrics: []
settings:
  - key: mention_role_ids
    type: string
    help: "Role IDs to mention, from the destination's allowed list"
  - key: publish_announcement
    type: boolean
```

### Behavior

- **Connect:** the owner enters relay URL, destination ID and relay token; the addon calls `GET /destinations/{id}` and creates the social account named "{server} · #{channel}". `provider_account_id` is the destination ID. The relay URL must be on the operator's allowlist (private Docker network address or HTTPS host), since it is a private destination.
- **Capabilities:** text limit, attachment count, size and types come from the destination's reported limits.
- **Publish:** POST the delivery; map the response as in sheet 10. Because the relay deduplicates by idempotency key, a retry after a timeout is safe (`remote_idempotency: true`).
- **Timing:** the sender polls every 5 seconds, so posts appear within seconds of the scheduled time.
- **Media:** Rails serves each attachment through a single-delivery `fetch_url` on its private relay media route; no public media origin is needed when YAGPDB and Rails share a network.
- **Metrics:** none in v1. Tracked-link clicks still appear in Insights.
- **Editing after delivery:** not supported in v1; edits to a delivered target create a new draft.

### Network

YAGPDB's web service must be reachable from the Rails worker, and Rails's relay media route must be reachable from YAGPDB's feeds service. On a single Docker host, put both on a shared private network and use internal addresses; otherwise use HTTPS for both directions.
